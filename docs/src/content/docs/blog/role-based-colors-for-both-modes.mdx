A theme palette should describe what a color does, not what hue it happens to be.

N0ctane maps its identity into roles such as primary, secondary, accent, and highlight. It also keeps surfaces, text, borders, and status states separate. This gives components a stable contract even when a project changes its brand colors.

Light and dark modes are configured independently. A light interface needs readable text, subdued surfaces, and darker accent text; it should not be a simple inversion of the dark palette.

Code is a separate environment. Syntax colors sit on a dedicated editor canvas and need enough contrast for comments, keywords, strings, functions, types, and punctuation to remain distinct. N0ctane 0.2.0 exposes a codePalette for each mode so those decisions are explicit.
