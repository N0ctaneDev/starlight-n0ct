N0ctane uses the upstream starlight-versions plugin for documentation archives, version-aware URLs, sidebars, notices, search, and the version selector.

<Badge tone="success">Enabled in this demo</Badge>

The demo shows the current v0.2.0 documentation and an archived v0.1.4 snapshot. Use the version selector in the sidebar to switch between them.

## Configuration

~~~js
versioning: {
  versions: [
    { slug: '0.1.4', label: 'v0.1.4', redirect: 'same-page' },
  ],
  current: {
    label: 'v0.2.0',
    redirect: 'same-page',
  },
  exclude: ['blog/**'],
},
~~~

The versions array is required when versioning is enabled. Each archived version supports:
- slug — URL directory and version identifier.
- label — optional UI label; defaults to the slug.
- redirect — same-page or root when switching versions.

current accepts label and redirect. exclude is an array of source-file glob patterns relative to src/content/docs/; excluded content always uses the current documentation version.

Set versioning: false or omit it to disable versioning.

## Content collection setup

Your project's src/content.config.ts must register the plugin's versions collection loader:

~~~ts
import { docsVersionsLoader } from 'starlight-versions/loader';

export const collections = {
  // Keep your existing docs and i18n collections.
  versions: defineCollection({ loader: docsVersionsLoader() }),
};
~~~

The N0ctane starter and demo already include this collection.

## Creating a new archive

When a configured version slug has no matching directory under src/content/docs/, the plugin archives the current documentation during the next astro dev or astro build.

Create one new version at a time: add one version entry, run the dev server or build so the plugin creates the archive, then add another version entry. This avoids the plugin's “Only one new version can be configured at a time” error.

Blog routes are excluded from versioning in the demo so posts remain under the same /blog/ URL.
