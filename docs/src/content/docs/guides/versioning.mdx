title: Versioning
description: Archive documentation releases and browse historical content.
---

N0ctane forwards the native starlight-versions configuration. The plugin creates a snapshot when a configured version is missing, then provides a version selector, version-aware navigation, and notices on archived pages.

The demo now presents current documentation as **v1.0.0** and keeps **v0.2.0** as its archived reference.

## Configure versions

~~~js
versioning: {
  versions: [
    { slug: '0.2.0', label: 'v0.2.0', redirect: 'same-page' },
  ],
  current: {
    label: 'v1.0.0',
    redirect: 'same-page',
  },
  exclude: ['blog/**'],
},
~~~

| Property | Description |
|---|---|
| versions | Required array of archived releases |
| versions[].slug | URL directory and version identifier |
| versions[].label | Optional selector label; defaults to the slug |
| versions[].redirect | same-page or root when switching versions |
| current.label | Label shown for the current, unarchived docs |
| current.redirect | Redirect behavior for the current version |
| exclude | Source-file glob patterns that remain outside the version archive |

## Register the versions collection

Add docsVersionsLoader to your Astro content config:

~~~ts
import { defineCollection } from 'astro:content';
import { docsVersionsLoader } from 'starlight-versions/loader';

export const collections = {
  // Keep your docs and i18n collections.
  versions: defineCollection({ loader: docsVersionsLoader() }),
};
~~~

The installer templates already include the loader.

## Create a release archive

When a configured slug does not exist under src/content/docs, the plugin creates the archive from current documentation on the next astro dev or astro build.

Create one new archive at a time:

1. Add one new version entry.
2. Run the dev server or build once to let the plugin create its snapshot.
3. Inspect the generated archive.
4. Only then add another new version.

Do not configure multiple missing versions at once; the upstream plugin intentionally handles one newly created version per run.

## Blog routes

Exclude the blog source from versioning when you want posts to keep stable URLs across documentation releases. The demo config uses blog/** in the exclude list.
