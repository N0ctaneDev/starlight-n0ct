The project configuration lives in `n0ct.config.mjs`. N0ctane expands the concise settings into native Starlight configuration. The public site URL and deployment base path are Astro settings, configured in `astro.config.mjs` with `site` and `base`; they are not N0ctane options.

## Minimal configuration

~~~js
// @ts-check

/** @satisfies {import('@n0ctanedev/starlight-n0ct').N0ctConfig} */
export default {
  title: 'Project Docs',
  description: 'Documentation for my project.',
  favicon: '/favicon.svg',
  sidebar: {
    topicDisplay: 'collapsible',
    topics: ['guides', 'reference'],
  },
};
~~~

The JSDoc satisfies annotation enables editor suggestions and validates your JavaScript config against N0ctConfig.

## Site URL and base path

Configure the canonical site URL and deployment subpath in `astro.config.mjs`, not in `n0ct.config.mjs`:

~~~js
export default defineConfig({
  site: 'https://example.com',
  base: '/docs', // use '/' when deploying at the domain root
  integrations: [starlight(n0ctane(n0ctConfig))],
});
~~~

Astro exposes this base path as `import.meta.env.BASE_URL`. N0ctane components such as `DocCard` use it to prefix root-relative internal links automatically. The optional `basePath` integration is separate: it rewrites supported Markdown and frontmatter links; it does not own or configure Astro's `site` or `base`.

## Sidebar topics

The sidebar has three presentations:

| topicDisplay | Behavior |
|---|---|
| collapsible | Native Starlight groups and nested navigation |
| list | Root topic list with the selected topic's navigation |
| dropdown | Compact topic selector above the selected topic's navigation |

String topics create title-cased groups with automatic directory children:

~~~js
sidebar: {
  topicDisplay: 'collapsible',
  topics: ['guides', 'reference'],
},
~~~

Object topics support more control:

~~~js
sidebar: {
  topics: [
    {
      label: 'Guides',
      id: 'guides',
      icon: 'lucide:book-open',
      link: '/guides/',
      directory: 'guides',
      collapsed: false,
    },
    {
      label: 'Reference',
      id: 'reference',
      icon: 'lucide:library',
      link: '/reference/',
      directory: 'reference',
      badge: { text: 'API', variant: 'tip' },
    },
  ],
},
~~~

Use link to identify a landing page, directory to choose the autogenerate source, items for manual entries, and autogenerate: false to prevent generated children. The icon property accepts local or Iconify names in the native collapsible presentation; dropdownIcon uses a built-in Starlight icon name.

List and dropdown modes delegate navigation to the upstream Sidebar Topics plugins. They require the topic schema extension and a destination for each topic. Advanced starlight.sidebar configuration cannot be combined with these plugin-backed modes.

## Named themes

A palette is a named identity with its own dark and light configuration:

~~~js
theme: {
  defaultTheme: 'n0ctane',
  themes: {
    n0ctane: {
      label: 'N0ctane',
      favicon: '/favicons/n0ctane.svg',
      colors: {
        dark: {
          palette: {
            primary: '#F25CFF',
            secondary: '#8C42FF',
            accent: '#00E5FF',
            surface: '#131626',
            text: '#E6EAF8',
          },
        },
        light: {
          palette: {
            primary: '#B72DBF',
            secondary: '#7540CE',
            accent: '#00AFC2',
            surface: '#FFFFFF',
            text: '#211D32',
          },
        },
      },
    },
  },
},
~~~

The four required design decisions are primary, accent, surface, and text. Secondary, highlight, highlight text, and background can be supplied or derived. Use codePalette when syntax colors need to differ from UI roles.

## Global and themed favicon

~~~js
export default {
  favicon: '/favicon.svg',
  theme: {
    themes: {
      n0ctane: { favicon: '/favicons/n0ctane.svg' },
      nord: { favicon: '/favicons/nord.svg' },
    },
  },
};
~~~

The root favicon is the fallback for every theme without an override. Paths are root-relative URLs to files in your project's public/ directory. Switching the active theme updates the browser favicon and the footer mark.

## Native Starlight escape hatch

Use starlight for native settings that do not have a N0ctane shorthand:

~~~js
starlight: {
  lastUpdated: true,
  tableOfContents: { minHeadingLevel: 2, maxHeadingLevel: 4 },
},
~~~

Advanced Starlight options are merged after N0ctane defaults. Custom components, CSS, sidebar, and plugins can intentionally replace defaults. See the [complete config reference](/reference/config-api/).


## Add features after setup

You can enable Blog, versioning, or any bundled integration after the project has been initialized. Run the CLI from the project directory:

~~~sh
npx @n0ctanedev/starlight-n0ct add blog
npx @n0ctanedev/starlight-n0ct add versioning
npx @n0ctanedev/starlight-n0ct add linksValidator
~~~

The Blog command asks for its route prefix and content directory, updates the docs schema, and creates a hidden first post. Versioning automatically excludes the configured Blog source path. See [Add features to an existing project](/guides/features/) for the complete workflow and package-manager options.
