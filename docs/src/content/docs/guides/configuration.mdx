N0ctane keeps n0ct.config.mjs focused on the decisions most documentation sites make. It then converts those settings into Starlight's native configuration.

## Minimal configuration

~~~js
export default {
  title: 'Project Docs',
  description: 'Documentation for my project',
  sidebar: {
    topics: ['guides', 'reference'],
  },
  theme: {
    colors: {
      dark: {
        palette: { primary: '#F25CFF', accent: '#00E5FF' },
      },
      light: {
        palette: { primary: '#B72DBF', accent: '#00AFC2' },
      },
    },
  },
};
~~~

A string topic creates a title-cased group and an autogenerate entry using that directory.

## Sidebar topics

| Property | Description |
|---|---|
| label | Visible group label |
| icon | Optional local or Iconify icon name |
| dropdownIcon | Built-in Starlight icon for list/dropdown mode |
| id | Stable topic identifier |
| link | Internal page path or external URL |
| directory | Content directory used for autogeneration |
| `autogenerate` | `false`, `true`, or `{ directory }` |
| items | Manually authored native Starlight entries |
| collapsed | Whether the group starts collapsed |
| `badge` | Badge text or `{ text, variant }` |

~~~js
sidebar: {
  topics: [
    'reference',
    { label: 'Guides', icon: 'lucide:book-open', link: '/guides' },
    {
      label: 'Manual links',
      autogenerate: false,
      items: [
        { label: 'Overview', link: '/manual/' },
        { label: 'Migration', link: '/manual/migration/' },
      ],
    },
  ],
},
~~~

For list and dropdown modes, every topic needs a destination and the upstream Sidebar Topics plugin owns generated navigation. The collapsible mode keeps native Starlight sidebar rendering.

## Colors and code palettes

Light and dark color roles are configured independently. Syntax highlighting has its own optional palette in each mode:

~~~js
theme: {
  colors: {
    dark: {
      palette: { primary: '#F25CFF', accent: '#00E5FF' },
      codePalette: {
        background: '#0D1020',
        foreground: '#E6EAF8',
        keyword: '#FF8DD6',
        string: '#9FE6B8',
      },
    },
    light: {
      palette: { primary: '#B72DBF', accent: '#00AFC2' },
      codePalette: {
        background: '#F3F1F8',
        foreground: '#29253D',
        keyword: '#92247E',
        string: '#08764D',
      },
    },
  },
},
~~~

See the [theme reference](/reference/theme/) for every syntax color and the mode-qualified CSS token convention.

## Icons

Lucide is included and enabled by default. Additional Iconify collections can be installed by your site and included here:

~~~js
icons: {
  iconDir: './src/icons',
  include: { lucide: ['*'] },
},
~~~

Sidebar topic icons and the site title accept the set:name format, such as lucide:book-open.

## Footer

~~~js
footer: {
  text: 'Built with N0ctOS',
  links: [{ label: 'GitHub', link: 'https://github.com/example/project', newTab: true }],
  icons: [{ icon: 'lucide:github', link: 'https://github.com/example/project', label: 'GitHub', newTab: true }],
},
~~~

## Advanced Starlight options

Use starlight when a native option does not need a N0ctane shorthand:

~~~js
starlight: {
  lastUpdated: true,
  tableOfContents: { minHeadingLevel: 2, maxHeadingLevel: 4 },
},
~~~

Advanced settings are merged after N0ctane defaults. You can deliberately override components, custom CSS, plugins, or the sidebar.
