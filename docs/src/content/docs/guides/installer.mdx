---
title: Project installer
description: Scaffold a complete N0ctane + Starlight documentation project.
---

N0ctane ships a project generator so a new documentation site does not need to be assembled by hand. It copies a deploy-ready starter, creates a project-specific configuration, installs Astro, Starlight, N0ctane, Lucide, the Blog schema dependency, and Vite, then installs the selected packages.

## Create a project

```sh
npx @n0ctanedev/starlight-n0ct init my-docs
```

The interactive setup asks for the site title, description, canonical URL, deployment base path, sidebar presentation, and optional integrations. It generates the project and installs dependencies using the detected package manager.

Use the default answers without prompts:

```sh
npx @n0ctanedev/starlight-n0ct init my-docs --yes
```

Scaffold without installing dependencies:

```sh
npx @n0ctanedev/starlight-n0ct init my-docs --no-install
```

Choose a package manager explicitly:

```sh
npx @n0ctanedev/starlight-n0ct init my-docs --pm pnpm
```

## What gets generated

The starter includes an Astro configuration, `n0ct.config.mjs`, a Starlight `content.config.ts` using `docsSchema`, `i18nSchema`, and the Blog schema extension, a root translation file, Lucide icons, working example pages, a `404.mdx`, an environment example, and a GitHub Pages deployment workflow.

The generated `package.json` explicitly includes `@iconify-json/lucide`, because `astro-icon` discovers Iconify collections from the consuming Astro project's dependencies. Vite is a direct development dependency so `loadEnv()` can read `.env` values inside `astro.config.mjs` even under strict package managers.

## Optional integrations

The generator lets you select the built-in integrations. Unselected integrations are written as `false` in `n0ct.config.mjs`; the theme packages still provide the plugin code. The base-path integration is selected automatically only when the configured base path is not `/`.

After generation:

```sh
cd my-docs
npm run dev
```

Read the generated `DEPLOY.md` before publishing, especially when the site is hosted below a repository subpath.

The generated `src/content.config.ts` merges Starlight's `docsSchema` with the Blog and Sidebar Topics schemas, and registers `i18nSchema` for translations. It also installs `starlight-blog` and `starlight-sidebar-topics` directly because the content config imports their schemas.
