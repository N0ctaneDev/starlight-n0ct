N0ctane separates **palette identity** from **appearance mode**. A visitor chooses a named theme such as N0ctane, GitHub, Catppuccin, Rosé Pine, Dracula, Nord, or Flexoki, then switches between Dark and Light. Each mode has its own independently configured colors.

## Named themes

Set the default palette and provide one or more named theme definitions:

~~~js
theme: {
  defaultTheme: 'n0ctane',
  themes: {
    n0ctane: {
      label: 'N0ctane',
      favicon: '/favicons/n0ctane.svg',
      logo: {
        dark: '/logos/n0ctane-dark.svg',
        light: '/logos/n0ctane-light.svg',
      },
      colors: {
        dark: {
          palette: {
            primary: '#F25CFF',
            secondary: '#8C42FF',
            accent: '#00E5FF',
            surface: '#131626',
            text: '#E6EAF8',
            highlight: '#2A85FF',
            highlightText: '#080A15',
            background: '#0B0D17',
          },
          brandGradient: 'linear-gradient(115deg, #F25CFF, #8C42FF, #00E5FF)',
        },
        light: {
          palette: {
            primary: '#B72DBF',
            secondary: '#7540CE',
            accent: '#00AFC2',
            surface: '#FFFFFF',
            text: '#211D32',
            highlight: '#286DCE',
            highlightText: '#FFFFFF',
            background: '#F6F5FB',
          },
          brandGradient: 'linear-gradient(115deg, #B72DBF, #7540CE, #00AFC2)',
        },
      },
    },
    github: {
      label: 'GitHub',
      favicon: '/favicons/github.svg',
      colors: {
        dark: { palette: { primary: '#4493F8', accent: '#3FB950', surface: '#161B22', text: '#E6EDF3' } },
        light: { palette: { primary: '#0969DA', accent: '#1A7F37', surface: '#FFFFFF', text: '#1F2328' } },
      },
    },
  },
},
~~~

Theme IDs must begin with a lowercase letter and contain lowercase letters, numbers, hyphens, or underscores. Labels default to a title-cased theme ID. The defaultTheme must match a key in themes.

## Core palette

Every mode accepts the following fields:

| Field | Purpose |
|---|---|
| primary | Main brand identity, prominent links, and primary actions |
| secondary | Supporting brand color; derived from primary and accent when omitted |
| accent | Focus, active controls, and interactive highlights |
| surface | Main panel/card surface |
| text | Main readable foreground |
| highlight | Highlighted surface |
| highlightText | Text on the highlight surface |
| background | Page background; derived from surface when omitted |

The resolver creates primary, secondary, and accent shade ramps from 50 through 950. It also derives secondary text, muted text, border, selection, interaction, and surface roles unless explicit overrides are provided.

## Semantic colors

Semantic colors are independent of the brand palette and can be configured for each mode:

~~~js
colors: {
  dark: {
    semantic: {
      success: { foreground: '#06D6A0' },
      warning: { foreground: '#FFD166' },
      danger: { foreground: '#FF4D6D' },
      info: { foreground: '#FF9F1C' },
    },
  },
},
~~~

Each semantic role accepts foreground, background, border, and text. When omitted, background and border are derived from the foreground and the active surface.

## Code syntax palette

Code colors are configured separately from the documentation UI. Each mode supports:

| Field | Meaning |
|---|---|
| background, foreground | Code canvas and base text |
| comment, keyword, string, number | Language syntax groups |
| function, type, variable | Identifiers and declarations |
| tag, attribute, punctuation | Markup and syntax punctuation |
| invalid | Invalid or illegal token highlight |

~~~js
colors: {
  dark: {
    codePalette: {
      background: '#0D1020',
      foreground: '#E6EAF8',
      comment: '#A3AED1',
      keyword: '#FF8DD6',
      string: '#9FE6B8',
      number: '#FFD18A',
      function: '#79DDF8',
      type: '#BDAAFF',
    },
  },
},
~~~

Expressive Code receives a dark and light syntax theme for every named palette. Theme IDs are formed as theme-id-dark and theme-id-light. N0ctane disables automatic system appearance switching for code themes so the code palette follows the active N0ctane preference.

## Fine-grained overrides

Use overrides when a semantic role needs a value that should not be derived from the core palette.

| Group | Roles |
|---|---|
| brand | primary, secondary, accent, highlight, highlightText |
| surfaces | void, base, surface, elevated, sunken, overlay, navigation, sidebar, code |
| text | primary, secondary, muted, subtle, inverse, accent, highlight, onAccent |
| borders | subtle, default, strong, focus |
| interactive | hover, active, selected |
| highlight | background, text, border, selectionBackground, selectionText |
| code | background, foreground, cursor, selectionBackground, lineHighlight, lineNumber, lineNumberActive, diffAdded, diffRemoved, tabs |

The code group includes diffAdded and diffRemoved (foreground, background, border, text) plus tabs (background, activeBackground, foreground, activeForeground, border).

## Brand gradients and effects

Set brandGradient inside each mode to control the default branded gradient used for text and divider lines. An explicit effects.gradients.brand or effects.gradients.divider can override the corresponding role.

Gradient roles include brand, brandSoft, monochrome, accent, canvas, shimmer, callout, card, cardHover, steps, fileTree, sidebar, sidebarActive, versionSelect, scrollbar, scrollbarHover, and divider.

Shadow roles include soft, float, callout, card, cardHover, control, popover, sidebar, sidebarActive, scrollbar, scrollbarHover, focus, tab, wordmark, and step.

Values are CSS values. N0ctane rejects declarations, URLs, and executable CSS expressions.

## Theme-aware logos

Each named theme can define its own logo for both appearance modes. Paths are root-relative files in your project's `public/` directory:

~~~js
theme: {
  themes: {
    n0ctane: {
      logo: {
        dark: '/logos/n0ctane-dark.svg',
        light: '/logos/n0ctane-light.svg',
      },
    },
    flexoki: {
      logo: {
        dark: '/logos/flexoki-dark.svg',
        light: '/logos/flexoki-light.svg',
      },
    },
  },
},
~~~

The header logo switches automatically with the active named theme and Dark/Light mode. When only one mode is supplied, it is used for both modes. Themes without a configured logo fall back to the logo set in `starlight.logo`.

For a theme-aware image in a custom Starlight hero, add `data-n0ct-themed-logo` to its image element. N0ctane updates that image using the same theme logo map and Astro's configured `base` path:

~~~yaml
hero:
  image:
    alt: Project logo
    html: '<img data-n0ct-themed-logo src="/logos/n0ctane-dark.svg" alt="Project logo" />'
~~~

## Global and themed favicons

The root favicon is the fallback for all palettes. Each named theme may override it:

~~~js
export default {
  favicon: '/favicon.svg',
  theme: {
    themes: {
      n0ctane: { favicon: '/favicons/n0ctane.svg' },
      github: { favicon: '/favicons/github.svg' },
    },
  },
};
~~~

Paths are root-relative and refer to files in the consuming site's public directory. The browser favicon and footer brand mark update when the active named theme changes.

## Layout and glow

~~~js
theme: {
  contentWidth: '58rem',
  sidebarWidth: '17rem',
  glow: 'balanced', // subtle | balanced | strong
},
~~~

contentWidth and sidebarWidth accept positive CSS lengths. glow controls the strength of the ambient page treatment.

## Mode-qualified CSS tokens

Every resolved token is available both as an active alias and as a mode-specific token. Examples:

- --n0ct-base and --n0ct-dark-base
- --n0ct-surface and --n0ct-light-surface
- --n0ct-primary-500 and --n0ct-dark-primary-500
- --n0ct-code-background and --n0ct-light-code-background
- --n0ct-gradient-brand and --n0ct-dark-gradient-brand

Use an active alias when a component should follow the current mode. Use a mode-qualified token when a component intentionally needs a fixed dark or light value.

## Backwards compatibility

The legacy theme.colors.dark and theme.colors.light shape still configures the built-in n0ctane palette when themes.n0ctane is not defined. New projects should use named themes to make future palette selection straightforward.
