## Typography

The theme uses **Space Grotesk Variable** for interface and body text and **Space Mono** for code.

## Semantic color system

N0ctane exposes design roles rather than hue-named variables. The original brand identity maps to stable roles:

| Role | Purpose |
|---|---|
| primary | Brand identity, links, and primary gradients |
| secondary | Supporting brand color |
| accent | Focus, active controls, and interactive highlights |
| highlight | Selected or emphasized content |
| base | Main page background |
| surface | Cards, panels, and content surfaces |
| text.primary | Main readable text |
| text.secondary | Body copy |
| text.muted | Supporting and metadata text |
| border | Separators and component outlines |
| success, warning, danger, info | Semantic status colors |

Dark and light values are tuned independently. The default light palette uses a darker primary text accent and stronger neutral contrast for readability.

## Configuration

~~~js
theme: {
  colors: {
    dark: {
      palette: {
        primary: '#F25CFF',
        secondary: '#8C42FF',
        accent: '#00E5FF',
        surface: '#131626',
        text: '#E6EAF8',
        highlight: '#2A85FF',
        highlightText: '#080A15',
        background: '#0B0D17',
      },
    },
    light: {
      palette: {
        primary: '#B72DBF',
        secondary: '#7540CE',
        accent: '#00AFC2',
        surface: '#FFFFFF',
        text: '#211D32',
        highlight: '#286DCE',
        highlightText: '#FFFFFF',
        background: '#F6F5FB',
      },
    },
  },
}
~~~

The four core palette values are primary, accent, surface, and text. Secondary, highlight, highlightText, and background are optional and are derived when omitted.

## Mode-qualified color tokens

Every resolved role is available under a mode-specific prefix, regardless of the active theme:

- --n0ct-dark-base, --n0ct-dark-surface, --n0ct-dark-text-primary
- --n0ct-light-base, --n0ct-light-surface, --n0ct-light-text-primary
- --n0ct-dark-primary-500, --n0ct-light-primary-500
- --n0ct-dark-code-background, --n0ct-light-code-background

The regular aliases (--n0ct-base, --n0ct-surface, --n0ct-text-primary, and so on) always follow Starlight's active color scheme. Both naming styles are available in CSS and the commonly-used mode-qualified roles are also registered as Tailwind tokens, for example bg-n0ct-dark-surface.

## Dedicated code palettes

Code syntax colors are configured separately from the documentation UI palette. Each mode accepts its own codePalette. Values are literal hex colors so Expressive Code can generate independent Shiki themes with predictable contrast.

~~~js
theme: {
  colors: {
    dark: {
      codePalette: {
        background: '#0D1020',
        foreground: '#E6EAF8',
        comment: '#A3AED1',
        keyword: '#FF8DD6',
        string: '#9FE6B8',
        number: '#FFD18A',
        function: '#79DDF8',
        type: '#BDAAFF',
        variable: '#E8ECFA',
        tag: '#72DCEB',
        attribute: '#F6A8D8',
        punctuation: '#C0CBE5',
        invalid: '#FF829A',
      },
    },
    light: {
      codePalette: {
        background: '#F3F1F8',
        foreground: '#29253D',
        comment: '#68627F',
        keyword: '#92247E',
        string: '#08764D',
        number: '#875400',
        function: '#00688F',
        type: '#5D3BA5',
        variable: '#29253D',
        tag: '#006F88',
        attribute: '#92266B',
        punctuation: '#514B64',
        invalid: '#B42345',
      },
    },
  },
}
~~~

You can omit any field and N0ctane will use the built-in mode default. The previous overrides.code API remains available and takes precedence for detailed cursor, selection, line-number, diff, and tab controls.

## Fine-grained role overrides

Place these under either mode's overrides object. Every field is optional.

| Group | Available roles |
|---|---|
| brand | primary, secondary, accent, highlight, highlightText |
| surfaces | void, base, surface, elevated, sunken, overlay, navigation, sidebar, code |
| text | primary, secondary, muted, subtle, inverse, accent, highlight, onAccent |
| borders | subtle, default, strong, focus |
| interactive | hover, active, selected |
| highlight | background, text, border, selectionBackground, selectionText |
| code | background, foreground, cursor, selectionBackground, lineHighlight, lineNumber, lineNumberActive, diffAdded, diffRemoved, tabs |

The code override group also accepts:
- diffAdded and diffRemoved: foreground, background, border, text.
- tabs: background, activeBackground, foreground, activeForeground, border.

## Semantic status colors

Statuses can be overridden independently in each mode:

~~~js
theme: {
  colors: {
    light: {
      semantic: {
        success: { foreground: '#087F5B' },
        warning: { foreground: '#875400' },
        danger: { foreground: '#B42345' },
        info: { foreground: '#A85A00' },
      },
    },
  },
}
~~~

## Layout and effects

The defaults use a 55rem reading width and a 17rem sidebar. Override theme.contentWidth and theme.sidebarWidth to change layout. Glow strength accepts subtle, balanced, or strong; the default is balanced.

The background glow is fixed to the viewport rather than scrolling with the document. Focus states remain visible and animations respect prefers-reduced-motion.
