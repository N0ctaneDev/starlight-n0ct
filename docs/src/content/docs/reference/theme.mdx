N0ctane separates **palette identity** from **appearance mode**. A visitor chooses a named palette such as N0ctane, GitHub, Catppuccin, Rosé Pine, or Dracula, then chooses Light or Dark. Both settings apply to the site UI and the matching Expressive Code syntax theme.

## Live palette playground

Use the controls to edit the entire theme for either appearance. Core colors are shown first; expandable groups expose surfaces, text, borders, semantic states, code-frame roles, syntax tokens, gradients, and shadows. The current page is the preview, including the theme picker, all N0ctane components, and actual Expressive Code frames.

## Named themes

Define multiple named palettes under `theme.themes`. Each theme has its own dark and light values, and `theme.defaultTheme` chooses the palette used for visitors without a saved preference.

~~~js
theme: {
  defaultTheme: 'n0ctane',
  themes: {
    n0ctane: {
      label: 'N0ctane',
      colors: {
        dark: {
          palette: {
            primary: '#F25CFF',
            accent: '#00E5FF',
            surface: '#131626',
            text: '#E6EAF8',
          },
        },
        light: {
          palette: {
            primary: '#B72DBF',
            accent: '#00AFC2',
            surface: '#FFFFFF',
            text: '#211D32',
          },
        },
      },
    },
    github: {
      label: 'GitHub',
      colors: {
        dark: {
          palette: {
            primary: '#4493F8',
            accent: '#3FB950',
            surface: '#161B22',
            text: '#E6EDF3',
          },
        },
        light: {
          palette: {
            primary: '#0969DA',
            accent: '#1A7F37',
            surface: '#FFFFFF',
            text: '#1F2328',
          },
        },
      },
    },
  },
},
~~~

Theme IDs must start with a lowercase letter and may contain lowercase letters, numbers, hyphens, and underscores. Labels are optional; when omitted, N0ctane formats the ID for display.

Each mode requires only four core colors:

| Color | Used for |
|---|---|
| `primary` | Brand identity, links, and primary gradients |
| `accent` | Focus, active controls, and interactive highlights |
| `surface` | Main card and panel surface |
| `text` | Main readable foreground |

Secondary, highlight, highlight text, and page background are derived when omitted. You can still provide those optional palette values to fine-tune the result.

The demo also includes **Catppuccin** (Mocha dark / Latte light), **Rosé Pine** (Main dark / Dawn light), and **Dracula** (Dracula Classic dark / Alucard Classic light), each with its own code syntax palette. These are complete starting presets; every color and effect remains editable.

## Appearance and saved preferences

The theme switcher has two independent controls. Its icon cycles between **Dark** and **Light**; its dropdown selects the named palette. Choosing GitHub while Dark is active applies GitHub's dark palette and GitHub's dark syntax theme. Changing to Light then selects GitHub's light values.

Preferences are saved in `localStorage` under `n0ct-theme-preferences` as a `{ mode, theme }` object. There is no automatic/system mode. The previous `starlight-theme` value is kept in sync for compatibility with integrations that read Starlight's appearance key.

## Backwards-compatible configuration

The original `theme.colors` shape continues to configure the built-in `n0ctane` palette when `theme.themes.n0ctane` is not supplied:

~~~js
theme: {
  colors: {
    dark: {
      palette: {
        primary: '#F25CFF',
        accent: '#00E5FF',
        surface: '#131626',
        text: '#E6EAF8',
      },
    },
    light: {
      palette: {
        primary: '#B72DBF',
        accent: '#00AFC2',
        surface: '#FFFFFF',
        text: '#211D32',
      },
    },
  },
},
~~~

New projects should use `theme.themes`; legacy configuration can be migrated one palette at a time.

## Mode-qualified color tokens

Every resolved role is available under a mode-specific prefix, regardless of the active theme:

- `--n0ct-dark-base`, `--n0ct-dark-surface`, `--n0ct-dark-text-primary`
- `--n0ct-light-base`, `--n0ct-light-surface`, `--n0ct-light-text-primary`
- `--n0ct-dark-primary-500`, `--n0ct-light-primary-500`
- `--n0ct-dark-code-background`, `--n0ct-light-code-background`

The regular aliases (`--n0ct-base`, `--n0ct-surface`, `--n0ct-text-primary`, and so on) follow the selected theme and mode. Both naming styles are available in CSS. The complete mode-qualified role set and the primary, secondary, and accent shade ramps are also registered as Tailwind tokens.

## Dedicated code palettes

Syntax highlighting is configured independently for each theme and appearance. When omitted, the built-in N0ctane code palette is used. Expressive Code receives a pair of named syntax themes for each palette: `<theme-id>-dark` and `<theme-id>-light`.

~~~js
theme: {
  themes: {
    github: {
      colors: {
        dark: {
          codePalette: {
            background: '#0D1117',
            foreground: '#E6EDF3',
            keyword: '#FF7B72',
            string: '#A5D6FF',
            comment: '#8B949E',
          },
        },
        light: {
          codePalette: {
            background: '#FFFFFF',
            foreground: '#1F2328',
            keyword: '#CF222E',
            string: '#0A3069',
            comment: '#6E7781',
          },
        },
      },
    },
  },
},
~~~

The full code palette supports `background`, `foreground`, `comment`, `keyword`, `string`, `number`, `function`, `type`, `variable`, `tag`, `attribute`, `punctuation`, and `invalid`.

## Fine-grained role overrides

Main palette colors are the starting point. Use `overrides` when a component needs a specific role that should not be derived from the four core colors. Overrides can be set independently for each theme and mode.

| Group | Available roles |
|---|---|
| `brand` | primary, secondary, accent, highlight, highlightText |
| `surfaces` | void, base, surface, elevated, sunken, overlay, navigation, sidebar, code |
| `text` | primary, secondary, muted, subtle, inverse, accent, highlight, onAccent |
| `borders` | subtle, default, strong, focus |
| `interactive` | hover, active, selected |
| `highlight` | background, text, border, selectionBackground, selectionText |
| `code` | background, foreground, cursor, selectionBackground, lineHighlight, lineNumber, lineNumberActive, diffAdded, diffRemoved, tabs |

The code override group also accepts `diffAdded` and `diffRemoved` (foreground, background, border, text), and `tabs` (background, activeBackground, foreground, activeForeground, border).

## Semantic status colors

Statuses can be overridden independently in each theme and mode:

~~~js
theme: {
  themes: {
    github: {
      colors: {
        light: {
          semantic: {
            success: { foreground: '#1A7F37' },
            warning: { foreground: '#9A6700' },
            danger: { foreground: '#CF222E' },
            info: { foreground: '#0969DA' },
          },
        },
      },
    },
  },
},
~~~

## Gradients and shadows

Gradients and shadows are configurable per theme and appearance through `colors.dark.effects` and `colors.light.effects`. The playground exposes each token under **Gradients and shadows**; edits are saved into the generated theme config.

~~~js
theme: {
  themes: {
    n0ctane: {
      colors: {
        dark: {
          effects: {
            gradients: {
              brand: 'linear-gradient(90deg, #F25CFF, #00E5FF)',
              divider: 'linear-gradient(90deg, #8C42FF, #00E5FF)',
              canvas: 'radial-gradient(circle at top left, #3B174A, transparent 40rem)',
            },
            shadows: {
              card: '0 12px 34px rgb(0 0 0 / 0.24)',
              focus: '0 0 0 3px rgb(0 229 255 / 0.2)',
            },
          },
        },
      },
    },
  },
},
~~~

Gradient roles cover brand text, heading/code separators, canvas glow, shimmer, callouts, cards, steps, FileTree, sidebar, version selector, and scrollbars. Shadow roles cover cards, callouts, controls, popovers, sidebar, focus, tabs, and other shared components. Values are validated as single CSS values; declarations, URLs, and executable expressions are rejected.

## Layout

The defaults use a 58rem reading width and a 17rem sidebar. Override `theme.contentWidth` and `theme.sidebarWidth` to change layout. Glow strength accepts `subtle`, `balanced`, or `strong`; the default is balanced.

The background glow is fixed to the viewport rather than scrolling with the document. Focus states remain visible and animations respect `prefers-reduced-motion`.
