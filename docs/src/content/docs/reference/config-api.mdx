title: Configuration API
description: The public N0ctConfig shape accepted by n0ct.config.mjs.
---

The package exports the N0ctConfig and N0ctaneOptions TypeScript interfaces. Add a JSDoc satisfies annotation to a JavaScript config to get editor completion and type checking.

~~~js
// @ts-check

/** @satisfies {import('@n0ctanedev/starlight-n0ct').N0ctConfig} */
const config = {
  title: 'Project docs',
  sidebar: { topics: ['guides', 'reference'] },
};

export default config;
~~~

## Root properties

| Property | Type | Default | Notes |
|---|---|---|---|
| title | string | Required | Starlight site title |
| description | string | — | Site description and metadata |
| favicon | string | /favicon.svg at runtime | Root-relative path to a file in public/ |
| sidebar | object | Starlight defaults | Topic display, topics, and extra entries |
| versioning | false or N0ctVersioningConfig | false | Native Starlight Versions options |
| integrations | object | All built-in integrations enabled unless false | Per-plugin options |
| footer | object | Theme footer | Footer text, links, and icon links |
| icons | object | src/icons and bundled Lucide | Local icon directory and Iconify allowlist |
| theme | N0ctThemeConfig | N0ctane defaults | Named palettes, layout, and effects |
| starlight | `Partial<StarlightUserConfig>` | — | Advanced native Starlight escape hatch |

## Astro site settings

`site` and `base` are configured in Astro's `astro.config.mjs`, not in `N0ctConfig`. Set `site` to the canonical deployment URL and `base` to the deployment subpath (or `/` at the domain root). Astro exposes `base` as `import.meta.env.BASE_URL`; N0ctane's `DocCard` uses that value when resolving root-relative internal destinations.

## Sidebar

| Property | Type | Purpose |
|---|---|---|
| topicDisplay | collapsible, list, dropdown | Select native groups, upstream list, or dropdown |
| topics | N0ctSidebarTopic[] | Root topics, shorthand directories, or manual groups |
| topicOptions.exclude | string[] | Route patterns excluded from plugin-backed topic routing |
| topicOptions.topics | `Record<string, string[]>` | Map otherwise-unlisted route patterns to topic IDs |
| extra | N0ctNativeSidebarItem[] | Append native Starlight entries |

A topic may be a directory string or an object with label, id, icon, dropdownIcon, link, directory, autogenerate, items, collapsed, badge, attrs, and translations. A string such as guides creates a title-cased group with children generated from that content directory. When the Blog integration is enabled, N0ctane automatically excludes its configured prefix from Sidebar Topics routing in list/dropdown modes. Blog posts should also use `sidebar.hidden: true` so they stay out of the native Starlight docs sidebar.

## Footer and icons

~~~js
footer: {
  text: 'Built with Starlight-N0ct',
  links: [
    { label: 'GitHub', link: 'https://github.com/example/project', newTab: true },
  ],
  icons: [
    { icon: 'lucide:github', link: 'https://github.com/example/project', label: 'GitHub', newTab: true },
  ],
},

icons: {
  iconDir: './src/icons',
  include: { lucide: ['*'] },
},
~~~

Footer links accept label, link, and optional newTab. Footer icon links accept icon, link, label, and optional newTab. The icons setting controls the local SVG directory and Iconify collection allowlist.

## Integrations

Each integration entry accepts false or an options object. The available keys are basePath, announcement, kbd, llmsTxt, scrollToTop, llmActions, sidebarSwipe, linksValidator, blog, and imageZoom. N0ctane forwards options to the upstream plugin; see the [integration reference](/reference/integrations/).

## Versioning

N0ctVersioningConfig mirrors the relevant upstream options:

~~~js
versioning: {
  versions: [
    { slug: '0.2.0', label: 'v0.2.0', redirect: 'same-page' },
  ],
  current: { label: 'v1.0.0', redirect: 'same-page' },
  exclude: ['blog/**'],
},
~~~

The versions array is required when versioning is enabled. Each version accepts slug, label, and redirect. current accepts label and redirect. exclude contains source-file glob patterns.

When versioning is enabled, register docsVersionsLoader() in a versions content collection. The installer templates include the loader.

## Theme

N0ctThemeConfig supports defaultTheme, themes, legacy colors, contentWidth, sidebarWidth, and glow. Each named theme supports label, favicon, optional dark/light `logo` paths, and colors. Logo paths point to files in the consumer project's `public/` directory. See the detailed [theme reference](/reference/theme/).
