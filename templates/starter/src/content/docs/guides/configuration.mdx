title: Configure your site
description: Customize sidebar topics, base paths, integrations, themes, and documentation versioning.
---

Edit `n0ct.config.mjs` to configure Starlight-N0ct. The file uses the public `N0ctConfig` shape and includes an editor hint through its JSDoc annotation.

## Sidebar topics

The default presentation uses native collapsible groups:

~~~js
sidebar: {
  topicDisplay: 'collapsible',
  topics: [
    { label: 'Guides', link: '/guides/', directory: 'guides' },
    { label: 'Reference', link: '/reference/', directory: 'reference' },
  ],
},
~~~

Use `list` to show root topics above the selected topic's navigation, or `dropdown` for a compact selector.

~~~js
sidebar: {
  topicDisplay: 'dropdown',
  topics: [
    { label: 'Guides', id: 'guides', link: '/guides/', directory: 'guides' },
    { label: 'Reference', id: 'reference', link: '/reference/', directory: 'reference' },
  ],
},
~~~

List and dropdown use the Sidebar Topics integration. Keep a `link` or `directory` on each root topic. The starter's content schema already includes `topicSchema`. Do not also set `starlight.sidebar` when using these plugin-backed modes.

## Site URL and base path

Astro owns the public site URL and deployment base path. They are not configured by N0ctane or `n0ct.config.mjs`. Set `SITE_URL` and `BASE_PATH` in `.env`; the template's `astro.config.mjs` passes them to Astro as `site` and `base`. For example, to deploy at `https://example.com/docs`:

~~~sh
SITE_URL=https://example.com
BASE_PATH=/docs
~~~

Use `/` for a domain-root site. The installer preselects the Base path rewriting integration when you enter a non-root base path. Keep it enabled when you want the plugin to prefix supported root-relative Markdown and frontmatter links:

~~~js
integrations: {
  basePath: {},
},
~~~

Astro exposes the configured path as `import.meta.env.BASE_URL`. N0ctane's `DocCard` automatically prefixes root-relative `href` values with this base, so `href="/guides/"` resolves to `/docs/guides/`. Absolute external URLs and fragment links are not changed.

The optional N0ctane `basePath` integration is separate: keep it enabled only if you also want its Markdown/frontmatter link rewriting. It does not set Astro's `site` or `base`.

## Integrations

Optional integrations are configured inside `integrations`. Set a key to `false` to disable it or use an options object to enable it.

~~~js
integrations: {
  llmsTxt: {},
  scrollToTop: {},
  sidebarSwipe: {},
  imageZoom: {},
  blog: false,
},
~~~

The docs starter keeps Blog disabled and does not ship sample blog posts. Its content schema already includes `blogSchema`, so you can enable Blog later with `blog: {}`. To start with a configured publication and sample posts, create a project with:

~~~sh
npx @n0ctanedev/starlight-n0ct init my-publication --template blog
~~~

See the built-in integrations reference for the complete list.

## Named themes

You can define your own palette using a named theme. Dark and Light are independent:

~~~js
theme: {
  defaultTheme: 'n0ctane',
  themes: {
    n0ctane: {
      label: 'N0ctane',
      colors: {
        dark: {
          palette: {
            primary: '#F25CFF',
            secondary: '#8C42FF',
            accent: '#00E5FF',
            surface: '#131626',
            text: '#E6EAF8',
          },
        },
        light: {
          palette: {
            primary: '#B72DBF',
            secondary: '#7540CE',
            accent: '#00AFC2',
            surface: '#FFFFFF',
            text: '#211D32',
          },
        },
      },
    },
  },
},
~~~

The root `favicon: '/favicon.svg'` points to the template's public icon. Each named theme may set its own `favicon` override. For the full token model, see the [theme reference](https://n0ctanedev.github.io/starlight-n0ct/reference/theme/).

## Icons

Lucide is installed as a direct project dependency. Use its `lucide:` prefix in site titles and topic configuration:

~~~js
title: '[lucide:terminal] My Documentation',
~~~

## Documentation versioning

N0ctane forwards the upstream Starlight Versions options through `versioning`. The starter already registers `docsVersionsLoader()` in `src/content.config.ts`. Versioning is disabled by default.

~~~js
versioning: {
  versions: [{ slug: '1.0', label: 'v1.0', redirect: 'same-page' }],
  current: { label: 'Latest', redirect: 'same-page' },
  exclude: ['blog/**', 'internal/**'],
},
~~~

Add one new archived version at a time. Run the dev server or a build so the plugin creates its snapshot before configuring another version. Exclude `blog/**` when blog posts should keep stable, unversioned URLs.

For all configuration options, see the [N0ctConfig API](https://n0ctanedev.github.io/starlight-n0ct/reference/config-api/).
